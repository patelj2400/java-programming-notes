## Java Comments

In **Java**, comments are non-executable lines in the source code.\
They are ignored by the compiler and are used to:

- Improve code readability

- Explain logic

- Add documentation

- Temporarily disable code during debugging

---

## 1.Single-Line Comment

#### Syntax:

    // This is a single-line comment

#### Example:

    public class Main {
        public static void main(String[] args) {
        // This prints Hello World
        System.out.println("Hello World");
        }
    }

#### When to use?

- Short explanations

- Inline clarification

- Debugging one line

---

## 2. Multi-Line Comment

#### Syntax:

    /*
    This is a
    multi-line comment
    */

#### Example:

    public class Main {
        public static void main(String[] args) {

            /*
                This program calculates
                the sum of two numbers
            */

            int a = 10;
            int b = 20;
            System.out.println(a + b);
        }

    }

#### When to use?

- Longer explanations

- Commenting multiple lines of code

- Temporary code removal

---

## 3. Documentation Comment (Javadoc)

Used for generating documentation.

Used to generate documentation using Javadoc tool.

#### Syntax:

    /**
    * This is a documentation comment
    */

These comments are processed by the **`javadoc` tool** (part of the JDK).

#### Example:

    /**
    * This class demonstrates addition.
    * @author Jay
    */
    public class Calculator {

        /**
        * Adds two integers.
        * @param a first number
        * @param b second number
        * @return sum of a and b
        */
        public int add(int a, int b) {
            return a + b;
        }
    }

Generate docs using:

    javadoc FileName.java

---

## Common Javadoc Tags

| Tag           | Meaning               |
| ------------- | --------------------- |
| `@author`     | Author name           |
| `@param`      | Parameter description |
| `@return`     | Return value          |
| `@throws`     | Exception description |
| `@deprecated` | Marks old method      |

---

## Important Notes

✔ Comments are ignored by the compiler
✔ They do not affect memory or runtime
✔ Comments do not increase program size (removed during compilation).
✔ Over-commenting is bad practice
✔ Nested comments are not allowed in Java.
✔ Code should be self-explanatory
✔ Javadoc comments start with /\*\* and end with \*/

## Bad Practice Example

    int a = 10; // assigning 10 to a

(This comment is unnecessary because the code is obvious.)

---

## Good Practice Example

    // Using Kadane's Algorithm to find maximum subarray sum

(Useful in DSA problems.)

## Best Practices (Especially for DSA)

- Comment **logic**, not syntax

- Explain **why**, not what

- Use Javadoc for reusable classes/methods

- Remove unnecessary comments before final submission
