# Packages in Java

In Java, a **package** is a namespace that organizes related classes and interfaces together.

---

## 1. Why Do We Need Packages?

1.  **Avoid Name Conflicts**\
    Two classes can have the same name if they are in different packages.

2.  **Better Organization**\
    Groups related classes (e.g., all utility classes in one package).

3.  **Access Control**\
    Packages help control visibility using access modifiers.

4.  **Reusability & Modularity**\
    Makes large projects structured and maintainable (important in DSA & real-world apps).

---

## 2. Types of Packages

#### 1. Built-in Packages

Provided by Java itself.

Examples:

- `java.lang` → Basic classes (String, Math, System)

- `java.util` → Utilities (Scanner, ArrayList, Collections)

- `java.io` → Input/Output classes

Example:

    import java.util.Scanner;

    class Test {
        public static void main(String[] args) {
            Scanner sc = new Scanner(System.in);
        }
    }

👉 `java.lang` is automatically imported.

---

#### 2. User-Defined Packages

You can create your own package.

##### Step 1: Create package

package mypackage;

    public class Hello {
        public void show() {
            System.out.println("Hello from package");
        }
    }

##### Step 2: Use package

import mypackage.Hello;

    class Test {
        public static void main(String[] args) {
            Hello obj = new Hello();
            obj.show();
        }
    }

---

## 3. How Java Stores Packages Internally

Package name corresponds to **folder structure**.

Example:

    package com.company.project;

Directory structure:

com/
└─ company/
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;└─ project/
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;MyClass.java

Compile:

    javac -d . MyClass.java

---

## 4. Import Statement Types

##### 1. Import Specific Class

    import java.util.ArrayList;

##### 2. Import Entire Package

    import java.util.\*;

##### 3. Fully Qualified Name (No Import)

    java.util.ArrayList list = new java.util.ArrayList();

---

## 5. Default Package

If you don't write a package statement, class belongs to **default package**.

⚠️ Not recommended for large projects.

---

## 6. Access Control & Packages (Important for Interviews)

| Modifier  | Same Class | Same Package | Different Package    |
| --------- | ---------- | ------------ | -------------------- |
| private   | ✅         | ❌           | ❌                   |
| default   | ✅         | ✅           | ❌                   |
| protected | ✅         | ✅           | ✅ (via inheritance) |
| public    | ✅         | ✅           | ✅                   |

---

## Naming Convention

Package names are:

- Lowercase

- Reverse domain name format

Example:

    com.google.util
    org.apache.commons

---

## Real-World Example

In large frameworks like:

- Spring Framework

- Hibernate

- Apache Maven

Packages organize thousands of classes logically.

Example:

    org.springframework.beans
    org.springframework.context
    org.hibernate.session

---

## How Packages Help in DSA

When solving DSA:

- You import `java.util.*` for:
  - ArrayList

  - HashMap

  - Stack

  - Queue

  - Collections

Packages help you:

- Quickly access utility classes

- Keep your own algorithms separate

- Organize large practice projects

---

## Interview-Level Points

1.  A class can belong to only **one package**.

2.  Package statement must be the **first line** (before import).

3.  Sub-packages are independent packages.
    - `java.util`

    - `java.util.concurrent`
