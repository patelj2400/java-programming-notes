# Variable Hiding

Variable hiding happens when a **child class declares a variable with the same name as a variable in its parent class**.

In this case, the child class variable **hides** the parent class variable.

This is different from **method overriding**.

---

## 1. Basic Example

    class Parent {
        int x = 10;
    }

    class Child extends Parent {
        int x = 20; // This hides Parent's x
    }

    public class Main {
        public static void main(String[] args) {
            Child obj = new Child();
            System.out.println(obj.x); // 20
        }
    }

### 👉 Output:

    20

### What happens?

- `Child` has its own `x`

- So `obj.x` refers to `Child`'s `x`

- Parent's `x` is hidden

### Example:

    class Parent {
        int x = 10;
    }

    class Child extends Parent {
        int x = 20; // This hides Parent's x
    }

    public class Test {
        public static void main(String[] args) {
            Parent p = new Child();
            System.out.println(p.x); // Output?
        }
    }

### 👉 Output:

    10

### Why Output is 10?

Because **variables are resolved at compile time** based on the **reference type**, not the object type.

Here:

    Parent p = new Child();

- Reference type → `Parent`

- So `p.x` refers to `Parent`'s variable.

---

## 2. How to Access Parent Variable?

Use `super` keyword.

    class Parent {
        int x = 10;
    }

    class Child extends Parent {
        int x = 20;

        void show() {
            System.out.println(x);        // 20 (child)
            System.out.println(super.x);  // 10 (parent)
        }

    }

---

## 3. Important Rule (Very Important for Interviews)

### Variables are NOT polymorphic

Variable access depends on **reference type**, not object type.

    Parent obj = new Child();
    System.out.println(obj.x); // 10

Even though object is `Child`,
`obj.x` prints `10` (Parent's variable).

✔ Because variable binding happens at **compile time**.

---

## 4. Why Variable Hiding is Not Recommended?

- Causes confusion

- Breaks readability

- Not true runtime polymorphism

Better practice:

- Use different variable names

- Or use `protected` carefully

---

## 5. Variable Hiding vs Method Overriding

| Feature      | Variable Hiding | Method Overriding |
| ------------ | --------------- | ----------------- |
| Polymorphism | ❌ No           | ✅ Yes            |
| Binding Time | Compile time    | Runtime           |
| Keyword Used | `super`         | `@Override`       |
| Based On     | Reference type  | Object type       |

---

## 6. Memory Concept (For DSA Understanding)

When:

    Parent obj = new Child();

Memory contains:

- Parent part

- Child part

But:

- Variable access → decided by reference (`Parent`)

- Method call → decided by object (`Child`)

---

## Important Points

✔ Variable hiding happens only with **instance variables** (not local variables).
✔ It is different from **method overriding**.
✔ Variables do **not** support runtime polymorphism.
✔ To access parent variable explicitly inside child: `Super`

---

## Final Interview Definition

> Variable hiding occurs when a subclass declares a variable with the same name as a variable in its superclass.
> Variable access is determined by reference type and resolved at compile time.
