# Function Overloading

## 1. What is Function Overloading?

**Function Overloading** means defining **multiple methods with the same name** in the same class but with **different parameters**.

It is an example of **Compile-Time Polymorphism** in Java. because the method call is resolved at compile time.

In simple words:

> Same method name + Different parameter list = Function Overloading

---

## 2. Why Do We Need It?

✔ Improves readability
✔ Same method name for similar operations
✔ Code reusability
✔ Cleaner API design

Example: `System.out.println()` is overloaded for int, double, String, etc.

---

## 3. Rules of Function Overloading

Two methods are overloaded if they differ in:

1.  **Number of parameters**

2.  **Type of parameters**

3.  **Order of parameters**

⚠️ Return type alone CANNOT differentiate overloaded methods.

✔ Compiler decides which method to call at compile time.

---

## Example 1: Different Number of Parameters

    class MathUtil {
        int add(int a, int b) {
            return a + b;
        }

        int add(int a, int b, int c) {
            return a + b + c;
        }

    }

✔ Same method name
✔ Different parameter count
✔ Valid overloading

---

## Example 2: Different Data Types

    class MathUtil {

        int add(int a, int b) {
            return a + b;
        }

        double add(double a, double b) {
            return a + b;
        }

    }

✔ Same method name
✔ Different parameter types
✔ Valid overloading

---

## Example 3: Different Order of Parameters

    class Display {
        void show(int a, String b) {
            System.out.println(a + " " + b);
        }

        void show(String b, int a) {
            System.out.println(b + " " + a);
        }

    }

✔ Same method name
✔ Different parameter order
✔ Valid overloading

---

## ❌ Invalid Overloading (Return Type Only)

    int add(int a, int b) { }
    double add(int a, int b) { } // ❌ Not allowed

👉 Compiler error because parameters are the same.

---

## How Java Decides Which Method to Call?

Java uses:

1.  **Exact match**

2.  **Type promotion**

3.  **Autoboxing**

4.  **Varargs**

Priority order:

    Exact Match > Widening > Autoboxing > Varargs

---

## Example with Type Promotion

    void show(int a) {
        System.out.println("int");
    }

    void show(double a) {
        System.out.println("double");
    }

    show(5); // int
    show(5.5); // double

If `show(int)` is removed, `show(5)` will call `show(double)` due to widening.

---

## Real Java Example: println()

The `println()` method in Java is overloaded many times in
Oracle Corporation's Java standard library.

It exists inside:

    java.io.PrintStream

Examples:

    System.out.println(10);
    System.out.println("Hello");
    System.out.println(true);
    System.out.println(3.14);

Same method name → different parameter types.

---

## Compile-Time Polymorphism

Function Overloading is:

- Resolved at **compile time**

- Also called **Static Binding**

- Faster than runtime polymorphism

---

## Overloading vs Overriding (Quick Difference)

| Feature              | Overloading  | Overriding      |
| -------------------- | ------------ | --------------- |
| Same method name     | ✔            | ✔               |
| Parameters different | ✔ Required   | ❌ Must be same |
| Inheritance required | ❌ No        | ✔ Yes           |
| Binding time         | Compile time | Runtime         |

---

## DSA Tip

In DSA practice, you often overload methods for:

- `printArray(int[])`

- `printArray(char[])`

- `printArray(String[])`

It keeps debugging clean.

In DSA and competitive coding, overloading helps when:

- You want the same operation for different data types.

- You want flexibility in the number of arguments.

- You want cleaner and readable code.

## Final Definition

> Function Overloading in Java is the process of defining multiple methods in the same class with the same name but different parameter lists, enabling compile-time polymorphism.
