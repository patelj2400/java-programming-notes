# Method Hiding (Static Methods)

## 1. What is Method Hiding?

👉 **Method Hiding happens when a subclass defines a `static` method with the same signature as a `static` method in its superclass.**

Because static methods belong to the **class**, not the object, they are **hidden**, not overridden.

---

## 2. Key Rule

| Feature          | Method Overriding         | Method Hiding                 |
| ---------------- | ------------------------- | ----------------------------- |
| Applies to       | Instance methods          | Static methods                |
| Polymorphism     | Runtime (Dynamic Binding) | Compile-time (Static Binding) |
| Depends on       | Object reference          | Reference type                |
| Uses `@Override` | Yes                       | No                            |

---

## Example of Method Hiding

    class Parent
    {
        static void show()
        {
            System.out.println("Parent static method");
        }
    }

    class Child extends Parent
    {
        static void show() { // Method Hiding
            System.out.println("Child static method");
        }
    }

    public class Main
    {
        public static void main(String[] args)
        {
            Parent obj = new Child();
            obj.show(); // Which method runs?
        }
    }

### Output:

    Parent static method

---

## Why?

Because:

    Parent obj = new Child();

Static methods are resolved at **compile time** using the **reference type (Parent)** --- not the object (`Child`).

So it calls:

    Parent.show()

NOT `Child.show()`

---

## Important Rules of Method Hiding

#### 1. Must have same signature

- Same method name

- Same parameters

#### 2. Cannot reduce access level

    class Parent
    {
        public static void show() {}
    }

    class Child extends Parent
    {
        private static void show() {} // ❌ Compilation Error
    }

### 3. Return type rules

- Must be same or covariant (like overriding rules)

### 4. Cannot override static method with non-static

    class Parent
    {
        static void show() {}
    }

    class Child extends Parent
    {
        void show() {} // ❌ Compile-time error
    }

---

## Method Hiding vs Overriding (Important Interview Question)

    class Parent
    {
        static void staticMethod()
        {
            System.out.println("Parent Static");
        }

        void instanceMethod()
        {
            System.out.println("Parent Instance");
        }

    }

    class Child extends Parent
    {
        static void staticMethod()
        {
        System.out.println("Child Static");
        }

        @Override
        void instanceMethod() {
            System.out.println("Child Instance");
        }

    }


    Parent obj = new Child();
    obj.staticMethod(); // Parent Static
    obj.instanceMethod(); // Child Instance

### Why difference?

- Static → compile-time binding → reference type

- Instance → runtime binding → object type

---

## Memory Concept (DSA + JVM Perspective)

When class loads:

- Static methods go to **Method Area (Metaspace)**

- They belong to the class structure

- No dynamic dispatch table is used

This is why **polymorphism does not apply to static methods**

---

## Interview Trick Questions

##### Q1: Is method hiding polymorphism?

👉 ❌ No. It is compile-time resolution.

##### Q2: Can we use `@Override` with static method?

👉 ❌ No. Compilation error.

##### Q3: Can we call hidden method using class name?

👉 ✅ Yes.

    Parent.show();
    Child.show();

---

## Real-World Analogy

Think of static methods like:

📌 Company policy manual
Each company (class) has its own manual.

If a child company writes a new manual with the same name, it doesn't override the parent's manual --- it hides it.

---

## Final Takeaway

✔ Static methods are **hidden**, not overridden
✔ Resolution happens at **compile time**
✔ Depends on **reference type**
✔ No runtime polymorphism
✔ Cannot mix static & non-static in override

---

## Key Interview Point

Static methods are not part of runtime polymorphism because they belong to the class, not the object.
