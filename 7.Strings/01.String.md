## String in Java

In Java, a **String** is a sequence [collection] of characters used to store text.

Example:

    String name = "Jay";

- String → Class

- name → reference variable (stored in stack)

- "Jay" → String object (stored in heap)'

---

## 1. What is a String in Java?

String is not a primitive.

- `String` is a **class** in Java.
- It belongs to the package `java.lang`.
- Strings in Java are **immutable** (cannot be changed after creation).

It is a class from Java’s class library.

Starts with capital letter → Class
Every string you create → Object of class String

    String s = "Hello";
    s.concat(" World");
    System.out.println(s); // Output: Hello

Why? Because `concat()` creates a new String object.

> Since java.lang is automatically imported, you don’t need to import String manually.

---

## 2. How Strings Are Stored in Memory (Important for DSA + Interviews)

#### A). String Pool (SCP -- String Constant Pool)

Java stores string literals in a special memory area called **String Pool** (inside Heap).

    String a = "Java";
    String b = "Java";

Here:

- Only **one object** is created in String Pool.

- `a` and `b` reference same object.

Compare:

    System.out.println(a == b); // true

##### Question:

Does this create 2 objects or 1?

- Only **one object** is created inside **String Pool**.

- Both `a` and `b` point to the same object.

##### What is String Pool?

> String Pool is: A special memory structure inside Heap that stores unique string values.

##### Why String Pool?

- Optimization.

If 100 variables have same value:

- Only 1 object is created

- Saves memory

---

#### B). Using `new` Keyword

    String a = new String("Java");
    String b = new String("Java");

- Two separate objects in heap.
- Outside String Pool
- Not stored in String Pool (unless `intern()` is used).

Compare:

    System.out.println(a == b); // false

## 3. Internal Structure of String

### In Java 8:

- Stored as `char[]`

### In Java 11+:

- Stored as `byte[]` + encoding flag

- Saves memory (Compact Strings feature)

---

## 4. Why String is Immutable?

✔ Security (used in class loading, file paths, URLs)\
✔ Thread-safe\
✔ Hashcode caching (important for HashMap)\
✔ String Pool optimization

Example:

    String s = "abc";

If mutable → HashMap keys would break!

Example:

If multiple users have password `"abc123"` stored in pool:

- If one modifies it → Everyone's password would change.

- To prevent this → Strings are immutable.

---

## 5. What is Immutability?

Once a String object is created, it **cannot be changed**.

Example:

    String a = "JAY";
    a = "JAYPATEL";

Did we modify `"JAY"`?

❌ No.

We created a **new object** `"JAYPATEL"`.

Old `"JAY"` becomes unreferenced → Garbage Collected.

## 6.Comparing Strings (==) vs equals() (Very Important Interview Question)

| Operator   | Checks                     |
| ---------- | -------------------------- |
| `==`       | Reference (memory address) |
| `equals()` | Content                    |

#### 1. Using ==

    a == b

Checks:

- Are both references pointing to SAME object?

Example:

    String a = "Jay";
    String b = "Jay";

    System.out.println(a == b); // true

Because both point to same pool object.

But:

    String a = new String("Jay");
    String b = new String("Jay");

    System.out.println(a == b); // false

Because different objects.

#### Using `.equals()`

    a.equals(b)

Checks:

- Do values match?

Example:

    String a = new String("Kunal");
    String b = new String("Kunal");

    System.out.println(a.equals(b)); // true

✔ Always use `.equals()` for value comparison.

## 7. Internally How println() Works

When you write:

    System.out.println(x);

Internally:

1.  Calls `valueOf()`

2.  Then calls `toString()`

3.  Converts everything into String

4.  Prints

That's why everything prints as text.

## 8. Printing Objects

If you print an object:

    System.out.println(arr);

It prints strange hash value.

Because:

- Default `toString()` is used.

- It prints memory representation.

To fix:

    Arrays.toString(arr);

This overrides default behavior.

## 9. Operators with Strings

#### 1.Character + Character

    System.out.println('a' + 'b');

Output:

    195

Because:

- 'a' = 97

- 'b' = 98

- 97 + 98 = 195

---

#### 2. String + String

    System.out.println("a" + "b");

Output:

    ab

Concatenation.

---

#### 3. String + Integer

    System.out.println("a" + 1);

Output:

    a1

Integer converted to wrapper class → `toString()` called.

---

#### Important Rule:

✔ `+` works:

- With primitives

- With Strings

- At least ONE operand must be String for concatenation

## 8. StringBuilder vs StringBuffer vs String

| Feature     | String                   | StringBuilder | StringBuffer |
| ----------- | ------------------------ | ------------- | ------------ |
| Mutable     | ❌ No                    | ✅ Yes        | ✅ Yes       |
| Thread-safe | ✅ Yes                   | ❌ No         | ✅ Yes       |
| Speed       | Slow (if modified often) | Fast          | Medium       |

👉 Use `StringBuilder` in DSA problems with heavy modification.

Example:

    StringBuilder sb = new StringBuilder("Hello");
    sb.append(" World");
    System.out.println(sb);
