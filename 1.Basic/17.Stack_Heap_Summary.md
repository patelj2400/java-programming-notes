# 1. Stack Memory

#### What it stores:

- Local variables

- Method calls

- **References (not objects)**

#### Example:

    int x = 10;
    String s = "Hello";

#### In Stack:

- `x → 10`

- `s → reference (points somewhere in heap/string pool)`

👉 Stack **never stores actual objects**, only references (except primitives).

---

# 2. Heap Memory

#### 📌 What it stores:

- All **objects**

- Arrays

- Instance variables

#### Example:

    String s = new String("Hello");

#### In Heap:

- A new `String` object `"Hello"` is created

#### In Stack:

- `s → reference to heap object`

---

# 3. String Pool (Special part of Heap)

#### What it is:

- A **special area inside heap**

- Stores **unique string literals**

#### Key idea:

Java **reuses strings** to save memory.

---

## Example 1 (String Pool Reuse)

    String a = "Hello";
    String b = "Hello";

#### What happens:

- Only **ONE "Hello"** is created in String Pool

#### Storage:

    Stack:         String Pool (Heap):
    a --------\
                --> "Hello"
    b --------/

👉 Both point to the **same object**

---

## Example 2 (`new` keyword)

    String a = "Hello";
    String b = new String("Hello");

#### What happens:

- `"Hello"` → String Pool

- `new String("Hello")` → **new object in heap**

#### Storage:

    Stack:        Heap:                 String Pool:
    a -------->   (nothing)             "Hello"
    b -------->   "Hello" (new obj)

👉 Now **two different objects exist**

---

## Example 3 (Comparison)

    String a = "Hello";
    String b = "Hello";
    String c = new String("Hello");

    System.out.println(a == b); // true
    System.out.println(a == c); // false

#### Why?

- `a` & `b` → same pool object

- `c` → different heap object

---

## Intern Method (Important)

    String s1 = new String("Hello");
    String s2 = s1.intern();

👉 `intern()` makes sure reference points to **String Pool**

---

## Key Differences

| Feature | Stack                 | Heap              | String Pool       |
| ------- | --------------------- | ----------------- | ----------------- |
| Stores  | Variables, references | Objects           | String literals   |
| Memory  | Fast, small           | Large             | Inside heap       |
| Sharing | No                    | No (usually)      | Yes (reused)      |
| GC      | Auto (method end)     | Garbage Collector | Garbage Collector |

---

## Simple Rule to Remember

👉 **Stack → "Who points?"**
👉 **Heap → "Actual objects"**
👉 **String Pool → "Shared strings"**

---

## Final Visualization

    Stack:        Heap:              String Pool:
    s1 -------->  String obj         "Hello"
    s2 -------->  (new object)
    s3 -------->  "Hello" (shared)
