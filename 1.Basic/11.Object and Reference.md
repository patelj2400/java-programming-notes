# Understanding Objects and Reference Variables (Memory Management – Java Focus)

## 1.What is an Object in terms of Memory?

In Java, when you create an object:

    Student s = new Student();

Two major things happen inside the JVM:

#### Step 1: Memory is allocated in the Heap

- `new Student()` creates an object in **Heap memory**.

- Heap stores actual object data (instance variables).

#### Step 2: Reference variable is created in Stack

- `Student s` is stored in **Stack memory**.

- It does NOT store the object.

- It stores the **memory address (reference)** of the object.

---

## 2.Stack vs Heap (Core Concept)

#### 🟦 Stack Memory

- Stores local variables

- Stores reference variables

- Stores method calls (stack frames)

- LIFO structure

#### 🟩 Heap Memory

- Stores objects

- Shared across threads

- Managed by Garbage Collector

---

## 3.Visual Memory Diagram

Example:

    class Student {
        int id;
    }

    public class Main {
        public static void main(String[] args) {
            Student s1 = new Student();
            s1.id = 101;
        }
    }

### What happens internally?

1.  `Student s1` → A **reference variable** is created in **Stack memory**

2.  `new Student()` → An **object** is created in **Heap memory**

3.  `s1` stores the **address (reference)** of that object

### Memory Representation:

| STACK       | HEAP           |
| ----------- | -------------- |
| s1          | Student Object |
| (reference) | id = 101       |

👉 `s1` holds the reference (address)\
👉 Actual object lives in heap

---

## 4.What Exactly is a Reference Variable?

A reference variable:

- Stores address of an object

- Does NOT contain actual object data

- Can point to different objects

- Can be null

Example:

    Student s1 = new Student();
    Student s2 = s1;

Memory:

STACK

    s1 ─┐
        ├───▶ Heap Object (Student)
    s2 ─┘

> Both `s1` and `s2` point to the SAME object.

---

## 5.Multiple References to Same Object

    Student s1 = new Student();
    Student s2 = s1;

### Memory Representation:

    STACK                HEAP

    s1 ─┐
        ├──────────────▶ [ Student Object ]
    s2 ─┘

✅ Both references point to the SAME object
❗ Changing via one reference affects the other

    s2.name = "Jatin";

> Now `s1.name` is also `"Jatin"`

---

## 6.Reassigning Reference

    Student s1 = new Student();
    Student s2 = s1;
    s1 = new Student();

Now:

    STACK                         HEAP
    ─────                         ────

    s1 ───────────────▶ [ Student Object 2 ]
    s2 ───────────────▶ [ Student Object 1 ]

> The first object still exists because `s2` points to it.

#### What happens internally?

- A **new object (Object 2)** is created in heap

- `s1` now points to Object 2

- `s2` still points to Object 1

- Object 1 is NOT deleted because `s2` still references it

---

## 7.What Happens When Reference Becomes Null?

Code:

    Student s1 = new Student();
    s1 = null;

Memory:

    STACK
    ───
    s1 = null

    HEAP
    ───
    Student Object (No reference)

Now:

- Object becomes **eligible for Garbage Collection** (in the JVM).
- Java uses automatic GC (in the JVM).
- JVM may delete it later

### When Does Garbage Collection Happen?

An object becomes **eligible for Garbage Collection** when:

- No reference variable is pointing to it

---

## 8.Multiple Objects Scenario

Code:

    Student s1 = new Student();
    Student s2 = new Student();

Memory:

    STACK
    ─────
    s1 ───▶ Object A
    s2 ───▶ Object B

    HEAP
    ────
    Object A
    Object B

Each `new` creates a separate object.

---

## 9.Object Creation Internals (Deep JVM)

When you write:

    new Student();

JVM does:

1.  Checks class in Method Area

2.  Allocates memory in Heap

3.  Initializes instance variables (default values)

4.  Calls constructor

5.  Returns reference to stack

---

## 10.Important Concept: Object vs Reference Variable

| Reference Variable         | Object              |
| -------------------------- | ------------------- |
| Stored in Stack            | Stored in Heap      |
| Holds memory address       | Holds actual data   |
| Created during declaration | Created using `new` |

---

## 11.String Special Case (Important for Interviews)

    String s1 = "Jay";
    String s2 = "Jay";

Only ONE object created in **String Constant Pool** (inside heap).

But:

    String s3 = new String("Jay");

Now TWO objects:

- One in String Pool

- One in Heap

This is a common tricky question.

---

## 12.Primitive vs Reference (Very Important)

    int a = 10;
    int b = a;

Memory:

    STACK
    -----
    a = 10
    b = 10

Primitive values are copied.

But for objects:

    Student s2 = s1;

Reference is copied, not object.

---

## 13.Method Call Example (Memory Deep Dive)

    void change(Student s) {
        s.id = 500;
    }

When called:

    change(s1);

What happens?

- Reference is copied to method stack frame

- Both point to same heap object

- Object is modified

Java is **pass-by-value**, but:

- For primitives → value copied

- For objects → reference value copied

## 14.Common Interview Traps

#### Trap 1

    Student s = null;
    s.id = 10;

👉 NullPointerException

#### Trap 2

    Student s1 = new Student();
    Student s2 = new Student();
    s1 = s2;

What happened to first object?

👉 It becomes eligible for GC (if no other reference exists)

## 15.Object Lifecycle in Memory

1.  Object Created (Heap)

2.  Referenced by Stack variable

3.  Used in program

4.  Becomes unreachable

5.  Garbage Collector removes it

---

## 16. Deep Memory Insight (Advanced Level)

In JVM:

- Stack memory is thread-specific

- Heap memory is shared

- Objects have:
  - Instance variables

  - Object header (for GC + synchronization)

  - Metadata pointer

The object structure is managed internally by the **JVM (Java Virtual Machine)** Java Virtual Machine.

## 16. Common Interview Questions

##### Q1: Where are objects stored?

👉 Heap memory

##### Q2: Where are reference variables stored?

👉 Stack (if local), Heap (if instance variable)

##### Q3: What happens when two references point to same object?

👉 Both modify same memory

##### Q4: When does object become eligible for GC?

👉 When no active reference points to it

##### Q5: Is Java Pass by Reference?

👉 No
Java is **Pass by Value**

But...

When passing objects:

- The **value of the reference (address)** is passed

- So method can modify object contents

- But cannot change original reference

Example:

    void change(Student s)
    {
        s = new Student();  // Won't affect original
    }

Because only copy of reference is passed.

## Final Summary (Must Remember)

| Concept            | Stored In | Stores                  |
| ------------------ | --------- | ----------------------- |
| Primitive Variable | Stack     | Actual value            |
| Reference Variable | Stack     | Address of object       |
| Object             | Heap      | Actual data             |
| String Pool        | Heap      | Reusable string objects |

---

- ✔ Objects → Heap
- ✔ References → Stack
- ✔ new → Allocates Heap memory
- ✔ Multiple references can point to one object
- ✔ Java is pass-by-value (reference value)
- ✔ GC removes unreachable objects
