# Garbage Collection

Garbage Collection (GC) is extremely important to understand **memory management + performance optimization**.

---

## 1.What is Garbage Collection?

**Garbage Collection (GC)** is the process by which the JVM automatically removes unused objects from memory (Heap).

👉 In simple words:

> If an object is no longer reachable, JVM deletes it to free memory.

In Java, memory management is **automatic** (unlike C/C++ where you manually free memory).

👉 GC automatically removes unused objects from memory to prevent memory leaks.

---

## 2.Why Garbage Collection is Needed?

In languages like **C/C++**, developers manually allocate and deallocate memory using `malloc()` and `free()`.

If they forget to free memory → **Memory Leak**.

But in **Java**, memory is managed automatically by the **Garbage Collector** inside the **Java Virtual Machine (JVM)**.

When we create objects:

    Student s1 = new Student();

Memory is allocated in **Heap**.

If we don't remove unused objects:

- Heap fills up

- Application slows down

- Eventually → `OutOfMemoryError`

GC prevents this.

---

## 3.How Memory is Structured in JVM

Memory mainly has:

- **Stack** → Stores reference variables & method calls

- **Heap** → Stores actual objects

Example:

    [ Stack ]       [ Heap ]
    s1 -----------> Student Object

If `s1 = null;`
Now no reference → object becomes **eligible for GC**

---

## 4.How Garbage Collection Works in Java

#### Step 1: Object Creation

When you create an object:

    Student s = new Student();

The object is created in **Heap Memory**.

#### Step 2: Object Becomes Unreachable

If:

    s = null;

Now the object has **no reference pointing to it** → It becomes eligible for GC.

#### Step 3: Garbage Collector Removes It

The JVM automatically removes that object and frees memory.

⚠️ Important: You cannot force GC, but you can request it using:

    System.gc();

But execution is not guaranteed.

---

## 5.When Does an Object Become Eligible for GC?

An object is eligible when:

### ✅ 1. Nullifying reference

    Student s = new Student();
    s = null;

### ✅ 2. Reassigning reference

    Student s1 = new Student();
    Student s2 = new Student();
    s1 = s2; // First object lost reference

### ✅ 3. Object created inside method

    void test() {
        Student s = new Student();
    }

After method ends → `s` destroyed → object eligible.

### ✅ 4. Anonymous object

    new Student();

---

## 6.How Garbage Collector Works Internally (GC Phases (Simplified))

JVM uses **Mark and Sweep Algorithm**

#### Step 1: Mark

Find reachable objects (from root references) (Identify unused objects)

#### Step 2: Sweep

Remove unreferenced objects

#### Step 3: Compact (in modern GC)

Rearrange memory to remove fragmentation

---

## 7.Types of Garbage Collectors in Java

In the Java Virtual Machine, different GC algorithms are used:

#### 1. Serial Garbage Collector

- Single-threaded

- For small applications

#### 2. Parallel Garbage Collector (Throughput GC)

- Multi-threaded

- Throughput focused

#### 3. CMS (Concurrent Mark Sweep) – Low Pause GC (deprecated)

- Low pause time

#### 4. G1 GC (Default in modern Java)

- Divides heap into regions

- Predictable pause times

#### 5. ZGC (Ultra Low Latency GC)

- Real-time financial systems

- Large-scale cloud systems

#### 6. Shenandoah GC (Red Hat Low Pause GC)

- Concurrent compaction

- Very low pause time

---

## 8.Memory Areas in JVM

1.  **Heap Memory** → Objects stored here

2.  **Stack Memory** → Method calls & local variables

3.  **Method Area** → Class metadata

GC mainly works on **Heap Memory**.

---

## 9.Generational Garbage Collection (Very Important for Interviews)

Heap is divided into:

    Young Generation

        - Eden
        - Survivor S0
        - Survivor S1

    Old Generation

    Metaspace (Class metadata)

### 🔹 Young Generation (Minor GC)

- New objects created here

- Minor GC happens here (fast)

### 🔹 Old Generation (Major GC)

- Long-living objects move here

- Major GC happens here (slow)

## 10.Advantages and Disadvantages of Garbage Collection

| Advantages                  | Disadvantages                   |
| --------------------------- | ------------------------------- |
| Automatic memory management | Slight performance overhead     |
| Prevents memory leaks       | Unpredictable timing            |
| Reduces programmer burden   | Not ideal for real-time systems |
| Improves security           |                                 |

## 13.Important Interview Questions

##### Q1:Does GC delete objects immediately?

👉 No. Only when JVM decides.

##### Q2: Is Java fully automatic memory management?

👉 Yes for heap.
No for resources like:

- Files

- DB connections

- Sockets

Use:

- `try-with-resources`

##### Q3: What causes memory leaks in Java?

👉 These are the causes:

- Static references

- Unclosed resources

- Listeners not removed

- Large collections not cleared

##### Q4: Can we force Garbage Collection in Java?

👉 No. We can request using `System.gc()`, but JVM decides.

##### Q5: Does GC remove objects with active references?

👉 No. Only unreachable objects are removed.

##### Q6: What is Stop-The-World?

👉 When GC runs, application threads pause temporarily.

##### Q7: Difference between finalize() and GC?

👉 GC destroys object memory; `finalize()` is a method called before destruction (now deprecated).
