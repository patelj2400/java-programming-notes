## Compile Time vs Runtime

---

### 1.What is Compile Time?

#### 👉 Definition:

**Compile Time** is the phase when the source code is converted into machine code (before execution).

- Happens **before the program runs**
- Errors detected here are called **Compile-time errors**

In Java, Compile Time is the phase when your **source code (.java)** is converted into **bytecode (.class)** by the compiler.

👉 **javac**

> In languages like **Java** and **C++**, many checks happen at compile time.

---

#### What Happens During Compile Time?

- Syntax checking

- Type checking

- Method signature validation

- Variable declaration validation

- Converts `.java` → `.class`

---

#### Example (Compile-Time Error)

    int x = "Hello"; // ❌ Type mismatch

Error happens because:

- Java is **statically typed**

- Type mismatch detected at compile time - program won’t run.

---

#### Characteristics of Compile Time

| Feature        | Description          |
| -------------- | -------------------- |
| Error Type     | Syntax / Type Errors |
| Speed          | Faster detection     |
| Safety         | More type safety     |
| When it occurs | Before program runs  |

---

### 2.What is Runtime?

#### Definition:

Runtime is the phase when your compiled program is **executing in memory**.

- Happens **after successful compilation**
- Errors detected here are called **Runtime errors**

In Java, execution happens inside:

👉 **Java Virtual Machine**

---

#### What Happens During Runtime?

- Object creation

- Method execution

- Memory allocation

- Garbage collection

- Exception handling

---

#### Example (Runtime Error)

    int a = 10;
    int b = 0;
    System.out.println(a / b); // ❌ ArithmeticException

This error occurs:

- Code compiles successfully

- But crashes during execution

- Languages like Python detect many errors at runtime.

---

#### Characteristics of Runtime

| Feature        | Description                |
| -------------- | -------------------------- |
| Error Type     | Logical / Exception errors |
| Hard to detect | Yes                        |
| Happens        | After compilation          |
| JVM involved   | Yes                        |

---

#### Compile Time vs Runtime (Side-by-Side)

| Feature      | Compile Time           | Runtime                                 |
| ------------ | ---------------------- | --------------------------------------- |
| When         | Before execution       | During execution                        |
| Checked By   | Compiler               | JVM                                     |
| Errors       | Syntax, Type errors    | Exceptions, Logic errors                |
| Example      | Missing semicolon      | NullPointerException / Division by zero |
| Speed impact | Improves runtime speed | Errors crash program                    |
| Performance  | Affects build time     | Affects execution speed                 |

### Real Interview Questions

##### Q1: What is Compile-Time Polymorphism?

→ Method Overloading
→ Resolved at compile time

    int add(int a, int b)
    double add(double a, double b)

---

##### Q2: What is Runtime Polymorphism?

→ Method Overriding\
→ Decided at runtime using Dynamic Method Dispatch

    class Animal {
    void sound() {}
    }

    class Dog extends Animal {
    void sound() { System.out.println("Bark"); }
    }

##### Q3: What is the difference between compile time and runtime?\*\*

👉 Compile time is when the source code is translated into bytecode or machine code, and syntax/type checking happens.\
👉 Runtime is when the compiled program is actually executed and logical errors or exceptions may occur.

##### Q4: Can a program have no compile-time errors but still fail?\*\*

→ Yes. If logical mistakes exist (e.g., dividing by zero, null access), the program will fail at runtime.

### DSA Perspective

##### Compile Time matters because:

- Java checks types strictly

- Generic type validation

- Prevents many runtime crashes

##### Runtime matters because:

- Memory management (Heap, Stack)

- Object creation

- Performance optimization

### Advanced Level Explanation (2--3 Years Experience)

---

At compile time, the compiler performs:

- Type checking

- Syntax validation

- Memory allocation planning

- Static binding (method overloading)

At runtime:

- Dynamic memory allocation happens

- Dynamic binding (method overriding)

- Garbage collection

- Exception handling

Example:

- Method **overloading → Compile-time polymorphism**

- Method **overriding → Runtime polymorphism**

---

### Advanced Interview Concept

##### Compile-Time Binding vs Runtime Binding

| Binding Type    | When         | Example                  |
| --------------- | ------------ | ------------------------ |
| Static Binding  | Compile Time | Private / Static methods |
| Dynamic Binding | Runtime      | Overridden methods       |
