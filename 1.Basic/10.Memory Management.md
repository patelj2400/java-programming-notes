## Memory Management

Memory management is one of the **most important core concepts** in Data Structures, Java, and System Design interviews.

It answers:

- Where is data stored?

- Who allocates memory?

- Who frees memory?

- How does performance depend on memory usage?

---

## 1.What is Memory Management?

Memory Management is the process of:

- Allocating memory to programs

- Tracking memory usage

- Deallocating unused memory

- Preventing memory leaks

- Optimizing performance

👉 It ensures efficient use of RAM.

**Memory Management = Process of allocating, using, and freeing memory efficiently.**

There are two major types:

| Type      | Who manages memory? | Example      |
| --------- | ------------------- | ------------ |
| Manual    | Programmer          | C, C++       |
| Automatic | JVM / Runtime       | Java, Python |

## 2.Memory Management in Java (Very Important)

In **Java**, memory is automatically managed by the JVM.

Java memory is divided into major areas:

### 1. Stack Memory

- Stores **method calls**
- Stores **local variables**
- Stores **reference variables**
- Thread-specific
- LIFO (Last In First Out)

---

### 2. Heap Memory

- Stores **Objects**
- Shared across threads
- Managed by Garbage Collector

---

### 3. Method Area (MetaSpace)

- Class metadata
- Static variables
- Method information
- Runtime constant pool

---

## 3.Stack vs Heap (Interview Table)

| Feature     | Stack                 | Heap              |
| ----------- | --------------------- | ----------------- |
| Stores      | Local variables       | Objects           |
| Size        | Smaller               | Larger            |
| Access      | Faster                | Slower            |
| Thread-safe | Yes (Thread-specific) | Shared            |
| Managed by  | JVM automatically     | Garbage Collector |

---

## 4.Garbage Collection (GC)

Java automatically removes unused objects using **Garbage Collection**.

In Java:

- Objects created using `new` are stored in Heap.

- If no reference points to an object → it becomes eligible for GC.

- GC automatically removes unused objects.

##### GC makes Java:

✔ Safer\
✔ Less memory-leak prone\
✔ Easier than C/C++

### What is Garbage?

An object with **no active reference**.

    Student s = new Student();
    s = null; // Now object becomes eligible for GC

## 6.Common Interview Questions

#### Q1: Where are objects stored in Java?

👉 Heap.

#### Q2: Where is reference variable stored?

👉 Stack.

#### Q3: Can stack memory cause memory leak?

👉 No (auto cleared after method ends).
👉 Stack memory is automatically cleared after method execution.

#### Q4: What is memory leak in Java?

👉 Memory leak happens when objects are no longer needed but still referenced, so GC cannot remove them.

#### Q5: What causes memory leak in Java?

- Unused objects still referenced
- Static collections holding unused objects
- Improper cache handling
- Unclosed database connections

#### Q6: Why is heap memory slower than stack?

- Heap involves dynamic allocation.

- GC overhead.

- Shared across threads.

#### Q6: What is OutOfMemoryError?

Occurs when:

- Heap space is full

- GC cannot free enough memory

---

## 7.Memory Leak Example in Java

    static List<Student> list = new ArrayList<>();

    public void add(Student s) {
    list.add(s); // Never removed → memory leak
    }

Because static list lives until application ends.
