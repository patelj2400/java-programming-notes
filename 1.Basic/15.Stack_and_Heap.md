## Stack Memory (Fast & Automatic)

![https://miro.medium.com/1%2AiFsZC_GQ229Sz8jPveAAUg.png](https://miro.medium.com/1%2AiFsZC_GQ229Sz8jPveAAUg.png)

![https://youshaohua.com/assets/img/post/simply-and-easily-understanding-function-call-stack-by-a-vision/thum.jpg](https://youshaohua.com/assets/img/post/simply-and-easily-understanding-function-call-stack-by-a-vision/thum.jpg)

- **What it stores:** Function calls, local variables

- **Memory management:** Automatic (managed by compiler)

- **Speed:** ⚡ Very fast

- **Size:** Limited (small)

- **Access pattern:** LIFO (Last In, First Out)

- **Example:** When you call a function, its variables go on the stack

👉 Think: _plates stacked on top of each other_

---

## Heap Memory (Flexible but Slower)

- **What it stores:** Objects, dynamic data

- **Memory management:** Manual (or Garbage Collector in languages like Java/Python)

- **Speed:** 🐢 Slower than stack

- **Size:** Large (depends on system)

- **Access pattern:** Random access

- **Example:** Objects created using `new`, `malloc`, etc.

👉 Think: _random boxes spread across a warehouse_

---

## Key Differences

| Feature    | Stack 🧠          | Heap 🧩               |
| ---------- | ----------------- | --------------------- |
| Allocation | Automatic         | Manual / GC           |
| Speed      | Fast              | Slower                |
| Size       | Small             | Large                 |
| Structure  | Ordered (LIFO)    | Unordered             |
| Use case   | Functions, locals | Objects, dynamic data |

---

## One-Line Summary

- **Stack = fast + temporary + automatic**

- **Heap = flexible + persistent + controlled**

## 🧠 Stack in Java (Method Calls & Local Variables)

![https://www.artima.com/insidejvm/ed2/images/fig5-9.gif](https://www.artima.com/insidejvm/ed2/images/fig5-9.gif)

- Stores **method calls** and **local variables**

- Each method creates a **stack frame**

- Automatically managed (no manual control)

- Very fast ⚡

### Example:

    public class Main {

        public static void main(String[] args) {
            int x = 10; // stored in stack
            int y = add(x); // function call → new stack frame
        }

        static int add(int a) {
            int result = a + 5;  // stored in stack
            return result;
        }

    }

👉 `x`, `y`, `a`, `result` → all in **stack**

## 🧩 Heap in Java (Objects & Instance Data)

![https://miro.medium.com/1%2AZiV5yog0LRrcvq5U0eoUsw.png](https://miro.medium.com/1%2AZiV5yog0LRrcvq5U0eoUsw.png)

![https://miro.medium.com/v2/resize%3Afit%3A1400/0%2AIa53oFwSgWllOk7d.png](https://miro.medium.com/v2/resize%3Afit%3A1400/0%2AIa53oFwSgWllOk7d.png)

- Stores **objects and instance variables**

- Created using `new`

- Managed by **Garbage Collector (GC)**

- Slower than stack but flexible

### Example:

    class Person {
        String name;
    }

    public class Main {

        public static void main(String[] args) {
            Person p = new Person(); // object in heap
            p.name = "Raj";
        }
    }

👉 `p` (reference) → **stack**\
👉 `new Person()` (object) → **heap**

---

## How Stack & Heap Work Together

    Person p = new Person();

- `p` → stored in **stack**

- Object → stored in **heap**

- Stack holds **reference (address)** of heap object

---

## Quick Comparison

| Feature    | Stack                    | Heap                   |
| ---------- | ------------------------ | ---------------------- |
| Stores     | Local variables, methods | Objects, instance data |
| Access     | Direct                   | Via references         |
| Management | Automatic                | Garbage Collector      |
| Speed      | Fast                     | Slower                 |
| Lifetime   | Short (method scope)     | Until no references    |

---

## One-Line Java Insight

👉 **Stack = references & local variables**
👉 **Heap = actual objects**
