# Stack vs Heap (Quick Idea)

| Memory Area | What it stores                            |
| ----------- | ----------------------------------------- |
| **Stack**   | Local variables, method calls, references |
| **Heap**    | Objects, instance data                    |

---

## Primitive vs Object (Important Difference)

### 1. Primitive

    int i = 5;

#### What happens here?

- `int` is a **primitive type**

- No object is created

- Stored directly in **stack memory**

- Faster access

- No reference involved

#### Storage:

    Stack:
    i → 5

👉 There is **NO heap usage** here.

---

### 2. Object Example

    Integer obj = new Integer(5);

#### What happens:

- `new Integer(5)` → object created in **heap**

- `obj` → reference stored in **stack**

#### Storage:

    Stack:          Heap:
    obj --------> Integer object (value = 5)

---

### 3. Another Example (Very Important)

    int[] arr = new int[3];

#### What happens:

- `arr` → stored in **stack (reference)**

- array object → stored in **heap**

#### Storage:

    Stack:          Heap:
    arr --------> [0, 0, 0]

---

## Why Java Uses Stack + Heap?

### Stack:

- Fast

- Automatically managed (method scope)

### Heap:

- Flexible (dynamic memory)

- Managed by **Garbage Collector**

---

## Key Rules to Remember

1.  **Primitive → Stack**

2.  **Object → Heap**

3.  **Reference → Stack (points to heap)**

4.  **Array → Heap (reference in stack)**

---

## Common Interview Insight

Even for objects:

    String s = "Hello";

- `"Hello"` → stored in **heap (String pool)**

- `s` → stored in **stack**

---

## Final Summary

| Code                            | Stack           | Heap           |
| ------------------------------- | --------------- | -------------- |
| `int i = 5;`                    | i → 5           | ❌             |
| `Integer obj = new Integer(5);` | obj (reference) | Integer object |
| `int[] arr = new int[3];`       | arr (reference) | array object   |
