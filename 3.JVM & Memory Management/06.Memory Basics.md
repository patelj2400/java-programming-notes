# Memory Basics in Java Perspective

---

# 1.What is Memory in Java?

Memory is the area where:

- Objects are stored

- Variables are stored

- Methods are executed

- Class metadata is stored

When you run a Java program, the **Java Virtual Machine (JVM)** manages memory automatically.

---

# 2.JVM Memory Structure (High-Level)

When a Java program runs, JVM divides memory into major parts:

JVM Memory (Runtime Memory Areas in Java)
├── Stack Memory\
 ├── Heap Memory\
 ├── Method Area (MetaSpace)\
 ├── PC Register\
 └── Native Method Stack

Let's understand the important ones.

---

# 3.Stack Memory (Thread-Level Memory)

#### What is Stack?

Stack stores:

- Method calls
- Stores function call information
- Local variables
- Primitive data types
- Object references (not objects)
- Works in LIFO (Last In First Out)
- Automatically managed

Each thread has its own stack.

---

#### Example:

    public class Main {
        public static void main(String[] args) {
            int x = 10;
            Person p = new Person();
        }
    }

#### Memory Breakdown:

- `x` → stored in Stack

- `p` → reference stored in Stack

- `new Person()` → object stored in Heap

---

#### Stack Characteristics

| Feature     | Stack                               |
| ----------- | ----------------------------------- |
| Size        | Small                               |
| Speed       | Very Fast                           |
| Stores      | Primitives + References             |
| Lifetime    | Until method ends                   |
| Thread Safe | Yes (each thread has its own stack) |

---

# 4.Heap Memory (Object Storage Area)

#### What is Heap?

Heap stores:

- Objects
- Instance variables
- Arrays
- Shared across methods
- Managed by Garbage Collector (in Java)

All threads share the heap.

---

#### Example:

    Person p1 = new Person();
    Person p2 = new Person();

Two objects are created in Heap.

---

#### Heap Characteristics

| Feature     | Heap               |
| ----------- | ------------------ |
| Size        | Large              |
| Speed       | Slower than Stack  |
| Stores      | Objects            |
| Managed by  | Garbage Collector  |
| Thread Safe | No (shared memory) |

---

# 5.Method Area (MetaSpace)

Stores:

- Class metadata

- Static variables

- Runtime constant pool

- Method bytecode

In Java 8+, it is called **MetaSpace**.

---

#### Example:

    class Person {
        static int count = 0;
    }

`count` is stored in Method Area (MetaSpace).

---

# 6.How Memory Works (Simple Flow)

When program runs:

1.  Code loads into memory

2.  `main()` goes into stack

3.  Variables go into stack

4.  Objects go into heap

5.  References stored in stack point to heap objects

# 8.Primitive vs Reference Memory

#### Primitive Type

    int a = 5;

- Value stored directly in Stack.

#### Reference Type

    Person p = new Person();

- Reference stored in Stack

- Actual object stored in Heap

---

# 9.Object Creation Memory Flow

When you write:

    Person p = new Person();

Step-by-step:

1.  JVM checks class metadata in Method Area

2.  Allocates memory in Heap

3.  Constructor runs

4.  Reference assigned to Stack variable

---

# 10.Garbage Collection (Very Important 🔥)

Java automatically removes unused objects from Heap using Garbage Collector.

If:

    p = null;

The object becomes eligible for garbage collection.

Managed by the JVM (you don't manually free memory like C/C++).

---

# 11.Memory in DSA Perspective

Understanding memory helps you:

- Avoid memory leaks

- Optimize space complexity

- Understand recursion stack overflow

- Design efficient data structures

- Handle large arrays & objects

---

#### Example: Recursion Stack

    void fun(int n) {
        if(n == 0) return;
        fun(n-1);
    }

Each recursive call adds a new stack frame.

Too deep recursion → StackOverflowError.

---

# 11.Stack vs Heap Quick Comparison

| Feature      | Stack                  | Heap              |
| ------------ | ---------------------- | ----------------- |
| Stores       | Local variables        | Objects           |
| Memory Mgmt  | Automatic (method end) | Garbage Collector |
| Speed        | Faster                 | Slower            |
| Thread Scope | Thread-specific        | Shared            |
| Size         | Limited (Smallar)      | Larger            |

---

# Interview Important Points

- Objects are stored in Heap

- References stored in Stack

- Static variables stored in MetaSpace

- Each thread has its own Stack

- StackOverflowError happens due to deep recursion

- Memory leak happens in Heap

# Important Interview Concepts

#### 📌 Object vs Reference

    Student s = new Student();

- `s` → stored in stack

- `new Student()` → stored in heap

---

#### 📌 Multiple References

    Student s1 = new Student();
    Student s2 = s1;

Both `s1` and `s2` point to **same object in heap**

- `s1` and `s2` → stored in stack

- `new Student()` → stored in heap
