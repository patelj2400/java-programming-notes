## 1.JIT Compiler (Just-In-Time Compiler)

A **JIT Compiler** is a part of the **Java Runtime Environment (JRE)** that improves performance by converting **bytecode into native machine code at runtime**.

#### Where It Is Used?

- **Java** → Inside the Java Virtual Machine (JVM)

- **C#** → Inside the .NET CLR

- JavaScript engines like V8

---

## 2.Where JIT Fits in Java Architecture

![https://softwareperformancenotes.github.io/img/jvmarch.jpg](https://softwareperformancenotes.github.io/img/jvmarch.jpg)

### Step-by-step execution:

1.  You write **Java source code (.java)**

2.  `javac` compiler converts it to **Bytecode (.class)**

3.  Bytecode runs inside the **Java Virtual Machine (JVM)**

4.  JVM uses:
    - **Interpreter** → Executes bytecode line by line

    - **JIT Compiler** → Converts frequently used bytecode into native machine code

---

## 3.Why Do We Need JIT?

Initially, JVM uses an **Interpreter**, which:

- Reads bytecode

- Converts it line-by-line

- Slower execution

If some code runs frequently (like loops), JIT:

- Detects "hot code"

- Compiles it into **native machine code**

- Stores it in memory

- Next time → runs directly (very fast ⚡)

Why JIT Is Faster?

- Frequently executed code is optimized

- Removes repeated interpretation

- Applies runtime optimizations (inlining, loop optimization)

---

## 4.How JIT Works (Important for Interviews)

#### 1.Method Invocation

When a method runs many times, JVM marks it as "hot".

#### 2.Compilation Trigger

JIT compiles that method into native code.

#### 3.Optimization

JIT performs:

- Method inlining

- Dead code elimination

- Loop unrolling

- Escape analysis

#### 4.Native Execution

Now method runs directly on CPU.

---

## 5.Interpreter vs JIT

| Feature          | Interpreter     | JIT Compiler        |
| ---------------- | --------------- | ------------------- |
| Speed            | Slower          | Faster              |
| Compilation Time | No compile time | Compiles at runtime |
| Optimization     | Minimal         | High optimization   |
| Best For         | Small code      | Repeated execution  |

---

## 6.JIT vs Normal Compiler

| Normal Compiler                 | JIT Compiler               |
| ------------------------------- | -------------------------- |
| Compiles before execution       | Compiles during execution  |
| Example: C, C++                 | Example: Java, C#          |
| Entire program compiled at once | Compiles parts when needed |

---

## 7.Types of JIT Compilers in Java

In modern Java (like **OpenJDK**):

#### C1 Compiler (Client Compiler)

- Faster compilation

- Less optimization

- Used for quick startup

#### C2 Compiler (Server Compiler)

- Slower compilation

- Highly optimized code

- Best for long-running apps

#### Tiered Compilation

Combination of C1 + C2 (default in modern JVM)

---

## 8.Real Example

    for(int i = 0; i < 1000000; i++) {
        sum += i;
    }

- First few iterations → Interpreter

- JVM detects loop is hot

- JIT compiles it

- Remaining iterations → Native machine speed

That's why Java becomes faster after some time (warm-up period).

---

## Important Interview Points

- JIT improves performance at runtime.

- It compiles only frequently used code.

- It works inside the JVM.

- It makes Java almost as fast as C++ in long-running systems.

- JVM uses adaptive optimization.
