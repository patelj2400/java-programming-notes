# Compiler vs Interpreter

---

## 1.What is a Compiler?

A **compiler** translates the **entire source code** into **machine code** before execution.

#### How It Works

1.  Write source code

2.  Compile it

3.  Get executable file

4.  Run executable

#### Example (C language)

    #include <stdio.h>
        int main() {
        printf("Hello World");
        return 0;
    }

Command:

    gcc program.c -o program
    ./program

Here, `gcc` compiles everything first, then runs.

#### Characteristics

- Translates whole program at once

- Generates executable file

- Faster execution

- Errors shown after full compilation

- Optimization possible

#### Examples of Compiled Languages

- C

- C++

- Go

- Rust

---

## 2.What is an Interpreter?

An **interpreter** translates and executes code **line by line** at runtime.

#### How It Works

1.  Read one line

2.  Translate it

3.  Execute it

4.  Move to next line

#### Example (Python)

    print("Hello World")

Run:

    python program.py

It executes line-by-line without creating a separate executable.

#### Characteristics

- Executes line by line

- No separate executable file

- Slower than compiled (usually)

- Stops at first error

- Easier debugging

#### Examples of Interpreted Languages

- Python

- JavaScript

- Ruby

- PHP

---

## 3.Key Differences (Interview Table)

| Feature        | Compiler                       | Interpreter          |
| -------------- | ------------------------------ | -------------------- |
| Translation    | Whole program                  | Line by line         |
| Speed          | Faster execution               | Slower execution     |
| Error Handling | Shows all errors after compile | Stops at first error |
| Output         | Generates executable file      | No executable file   |
| Optimization   | High                           | Limited              |
| Example        | C, C++                         | Python, JS           |

## 4.Where Does Java Fit?

This is the **most asked interview question**.

👉 Java uses **both**.

#### Step 1: Compilation

`javac` converts `.java` → **Bytecode (.class)**

#### Step 2: Interpretation + JIT

Java Virtual Machine executes bytecode using:

- Interpreter (initially)

- JIT Compiler (for optimization)

So Java is:

> 🔥 Compiled + Interpreted (Hybrid model)

That's why Java is **platform independent**.

> A compiler translates the whole program at once and generates machine code, while an interpreter translates and executes code line by line. Compiled programs run faster, while interpreted languages are easier to debug.

## Interview Questions

##### Q1. Why is compiled language faster?

- Because it is converted directly into machine code before execution, so the CPU runs it immediately without translating line-by-line at runtime.

##### Q2. Is Python purely interpreted?

- No.
  Python is both compiled and interpreted. It first compiles to bytecode (.pyc), then the Python Virtual Machine (PVM) interprets that bytecode.

##### Q3. Why is Java called platform independent?

- Because Java compiles code into bytecode, which runs on the JVM (Java Virtual Machine).
  Any system with a JVM can run the same .class file — “Write Once, Run Anywhere”.

##### Q4. Difference between JIT and normal compiler?

- Normal Compiler → Converts entire code to machine code before execution.

- JIT (Just-In-Time) → Compiles bytecode to machine code during runtime for better performance (used in JVM).

##### Q5. What happens at compile time vs runtime?

**Compile Time:**

- Syntax checking

- Type checking

- Converts source code to bytecode/machine code

**Runtime:**

- Program execution

- Memory allocation

- Method calls

- Exceptions handling
