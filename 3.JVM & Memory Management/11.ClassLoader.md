# ClassLoader in Java

When you run a Java program, classes (`.class` files) are **not loaded all at once**. They are loaded **dynamically when needed** by a component called the **ClassLoader**.

In simple words:

> **ClassLoader is a part of JVM that loads class files into memory at runtime.**

It belongs to the core of the Java Virtual Machine architecture.

---

## 1.Why ClassLoader is Needed?

- Java programs are compiled into **bytecode (.class files)**
- JVM does not load all classes at once
- It loads classes **on demand**
- ClassLoader brings the class into **Method Area (Metaspace)**

When you write:

    Student s = new Student();

Before creating the object:

1.  JVM must find `Student.class`

2.  Load it into memory

3.  Convert bytecode into runtime structure

4.  Then create the object

This entire loading process is handled by **ClassLoader**.

---

## 2.How Class Loading Works (Step-by-Step)

Class loading happens in **3 main phases**:

### 1).Loading

- JVM finds the `.class` file

- Loads bytecode into memory

- Creates a `Class` object

Example:

    Class c = Class.forName("Student");

This forces JVM to load the class.

---

### 2).Linking

Linking has 3 steps:

#### ✔ Verification

Checks:

- Bytecode correctness

- Security

- No illegal memory access

#### ✔ Preparation

- Allocates memory for static variables

- Assigns default values

Example:

    static int x = 10;

During preparation → `x = 0`\
After initialization → `x = 10`

#### ✔ Resolution

- Replaces symbolic references with actual memory references

---

### 3).Initialization

- Executes static blocks

- Assigns actual static variable values

Example:

    static {
        System.out.println("Class Loaded");
    }

This runs only once when class is initialized.

---

## 3.Types of ClassLoaders in Java

Java has **three built-in class loaders**:

#### 1).Bootstrap ClassLoader

![https://docs.oracle.com/cd/E19501-01/819-3659/images/dgdeploy2.gif](https://docs.oracle.com/cd/E19501-01/819-3659/images/dgdeploy2.gif)

- Loads core Java classes

- Written in native code (C/C++)

- Loads classes from `rt.jar` (Java 8) or Java base modules (Java 9+)

Examples of classes it loads:

- `java.lang.String`

- `java.lang.System`

- `java.util.ArrayList`

---

#### 2).Extension (Platform) ClassLoader

- Loads classes from `ext` folder (Java 8)
- From platform modules in Java 9+
- Parent = Bootstrap ClassLoader
- Handles extension libraries

---

#### 3) .Application (System) ClassLoader

- Loads classes from:
  - Classpath

  - Your project folders

  - External JARs

Example:\
Your `Main.class` is loaded by **Application ClassLoader**

---

## 4.ClassLoader Hierarchy (Parent Delegation Model)

Java follows **Parent Delegation Model**:

When a class is requested:

1.  Application ClassLoader checks

2.  Delegates to Extension

3.  Delegates to Bootstrap

4.  If not found → goes back down

This prevents:

- Core class overriding

- Security issues

Example:\
If you create your own `String` class,\
JVM will still load original `java.lang.String`.

---

## How Class Loading Works (Phases)

1.  **Loading** → Reads `.class` file

2.  **Linking**
    - Verification

    - Preparation

    - Resolution

3.  **Initialization** → Executes static blocks & static variables

---

## Important Methods of ClassLoader

    loadClass(String name)
    findClass(String name)
    defineClass()
    getClassLoader()

Example:

    ClassLoader cl = Student.class.getClassLoader();
    System.out.println(cl);

Output:

    jdk.internal.loader.ClassLoaders$AppClassLoader

---

## Custom ClassLoader

You can create your own ClassLoader by extending:

    class MyLoader extends ClassLoader
    {
        @Override
        protected Class<?> findClass(String name) {
            // custom loading logic
        }
    }

Used in:

- Application servers

- Plugin systems

- Hot reloading

- Frameworks

Example:

- Apache Tomcat uses custom class loaders for web apps isolation.

## Real Interview Points 🔥

##### 1.What is difference between Class.forName() and loadClass()?

| Feature               | Class.forName() | loadClass() |
| --------------------- | --------------- | ----------- |
| Loads class           | ✅              | ✅          |
| Initializes class     | ✅              | ❌          |
| Executes static block | ✅              | ❌          |

---

##### 2.Can we override Bootstrap ClassLoader?

❌ No --- it's native and part of JVM.

---

##### 3.When is a class loaded?

- When object is created

- When static method is used

- When static variable is accessed

- When `Class.forName()` is called

## ClassLoader in DSA Perspective

For DSA interviews:

- Static variables memory → prepared during class loading

- Time complexity of class loading is not counted in algorithm runtime

- Static blocks useful for precomputation

Example:

    static int[] fact = new int[1000];

Precomputed once during class loading.

## Quick Summary

ClassLoader:

- Part of JVM

- Loads `.class` files

- Works at runtime

- Follows Parent Delegation Model

- Has 3 phases: Loading → Linking → Initialization

- Has 3 main types: Bootstrap → Extension → Application

---

## Important Points

- ClassLoader follows Parent Delegation Model
- Classes are loaded only once
- Prevents duplicate class loading
- Helps in security
