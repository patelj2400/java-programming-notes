# Execution Flow of Java Program (Step-by-Step Deep Explanation)

---

## Step 1: Writing Source Code

You write Java code in a file:

    class Hello {
        public static void main(String[] args) {
            System.out.println("Hello World");
        }
    }

This file is saved as:

Hello.java

This is called **Source Code**.

---

## Step 2: Compilation (javac)

When you run:

    javac Hello.java

👉 The **Java Compiler** (part of JDK) converts source code into **Bytecode**.

Output file:

    Hello.class

This `.class` file contains **bytecode**, not machine code.

---

## Step 3: JVM Comes Into Picture

When you run:

    java Hello

Now the **JVM (Java Virtual Machine)** starts executing the program.

---

## Step 4: Class Loading Phase

### Component: Class Loader Subsystem

The **Class Loader** loads `.class` file into memory.

There are 3 main class loaders:

1.  Bootstrap ClassLoader

2.  Extension ClassLoader

3.  Application ClassLoader

Flow:

    Hello.class → Loaded into Method Area

---

## Step 5: Linking Phase

After loading, JVM performs:

### 1. Verification

Checks:

- Is bytecode valid?

- Is it secure?

- No illegal memory access?

### 2.Preparation

- Static variables are allocated memory

- Default values assigned

### 3.Resolution

- Converts symbolic references into direct references

---

## Step 6: Initialization Phase

Now:

- Static variables get actual values

- Static blocks execute

- Static methods become ready

Example:

    static int x = 10;
    static {
        System.out.println("Static block executed");
    }

This runs **before main()**.

---

## Step 7: Execution Starts (main method)

JVM looks for:

    public static void main(String[] args)

Why this signature?

- `public` → JVM must access it

- `static` → No object needed

- `void` → No return

- `String[] args` → Command line arguments

Now execution begins line by line.

---

## Step 8: Memory Allocation During Execution

When program runs, memory is divided mainly into:

### 1.Method Area

- Class metadata

- Static variables

- Runtime constant pool

### 2.Heap

- Objects are created here

- Instance variables stored

Example:

    Student s = new Student();

`Student object` → stored in **Heap**

---

### 3.Stack

- Each method call creates a stack frame

- Local variables stored here

Example:

    int a = 5;

`a` → stored in stack frame of main()

---

### 4.PC Register

- Stores current instruction address

---

### 5.Native Method Stack

- For native methods (C/C++ calls)

---

## Step 9: Execution Engine

The Execution Engine has:

#### Interpreter

- Reads bytecode line by line

- Converts to machine code

#### JIT Compiler

- Frequently used code compiled into native machine code

- Improves performance

So Java is:

> Compiled + Interpreted language

---

## Step 10: Garbage Collection

When objects have:

- No reference

JVM automatically removes them from heap.

Example:

    Student s1 = new Student();
    s1 = null;

Old object becomes eligible for GC.

---

### Example:

#### Step-by-step execution:

1.  Write code → Save as Test.java

2.  Compile → `javac Test.java`

3.  Bytecode generated → Test.class

4.  Run → `java Test`

5.  JVM loads class into memory

6.  Verifies bytecode

7.  Allocates memory

8.  Calls main() method

9.  Executes code

10. Prints output

---

## Interview Important Points

✅ JVM loads class before execution
✅ Static block runs before main
✅ Objects stored in heap
✅ Local variables stored in stack
✅ JIT improves performance
✅ GC works only on heap

---

## Advanced Interview Twist

### Q: Can JVM execute program without main()?

Yes --- in older Java versions using static blocks (not recommended).
