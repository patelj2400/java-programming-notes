## AOT (Ahead Of Time Compilation)

**AOT (Ahead Of Time Compilation)** means:

> 👉 Converting bytecode into machine code **before the program runs**.

This is opposite of **JIT (Just In Time compilation)**, where compilation happens **during runtime**.

#### Key Features

- Faster startup time 🚀

- No need for runtime compilation

- Better performance predictability

- Platform dependent (compiled for specific OS/CPU)

---

## 1.Where AOT is Used

In Java ecosystem, AOT is used in:

- Modern JVM improvements

- Android Runtime (ART)

- GraalVM Native Image

- Spring Native / Quarkus

- Microservices optimization

---

## 2.Normal Java Execution (Without AOT)

#### Step 1: Write Java Code

    class Test {
        public static void main(String[] args) {
            System.out.println("Hello");
        }
    }

#### Step 2: Compile

    javac Test.java

➡ Generates **bytecode (.class)**

#### Step 3: Run

    java Test

Here's what happens:

    Bytecode → JVM → JIT → Machine Code → CPU executes

Compilation happens at runtime.

---

## 3.What AOT Does

    Source Code → AOT Compiler → Native Machine Code → Run directly on OS

With AOT:

    Bytecode → Machine Code (before execution)

So when program runs:

    Machine Code → Directly executed

No JIT warm-up time.

---

## 4. AOT vs JIT

| Feature              | AOT                      | JIT               |
| -------------------- | ------------------------ | ----------------- |
| Compilation Time     | Before runtime           | During runtime    |
| Startup Speed        | Faster                   | Slower initially  |
| Runtime Optimization | Limited                  | Very high         |
| Memory Usage         | Lower                    | Higher            |
| Best For             | Microservices, CLI tools | Long-running apps |
| Example              | C, Rust                  | HotSpot JVM       |

---

## 5. AOT in Android (Very Important)

### Android Runtime (ART)

![https://source.android.com/docs/core/runtime/images/jit-arch.png](https://source.android.com/docs/core/runtime/images/jit-arch.png)

Before Android 5.0:

- Android used Dalvik (JIT-based)

After Android 5.0:

- ART introduced AOT compilation

### What Happens?

When you install an app:

    DEX bytecode → Compiled into native machine code

So:

- App opens faster

- Less runtime compilation

- Better battery performance

---

## 6. AOT in Java (Modern JVM)

### GraalVM

![https://miro.medium.com/v2/resize%3Afit%3A1400/0%2ARFN2GgNSKoP9JiSd.jpg](https://miro.medium.com/v2/resize%3Afit%3A1400/0%2ARFN2GgNSKoP9JiSd.jpg)

GraalVM allows:

    Java Code → Native Executable (.exe / binary)

No JVM needed at runtime.

### Example:

    native-image MyApp

Output:

    ./myapp (runs like C++ executable)

---

### Example Languages Using AOT

- **C / C++** → Compiled by GCC

- **Go** → Uses native compilation

- **Rust** → Native compilation

- **Java (with AOT tools)** → e.g., GraalVM Native Image

---

## Real World Usage

AOT is heavily used in:

- Microservices (Spring Boot native image)

- Serverless (AWS Lambda cold start reduction)

- CLI tools

- Android apps

- Containers (low memory footprint)

---

## Deep Understanding (DSA Perspective)

In DSA interviews, they may ask:

👉 Why is AOT better for microservices?

Because:

- Microservices start frequently

- Cold start time matters

- Memory footprint must be small

But for long-running systems:

- JIT is better (better runtime optimization)

---

## Simple Analogy

Think of:

- **JIT** = Cook food after customer orders (fresh, optimized)

- **AOT** = Pre-cooked food ready to serve (fast startup)

---

## Interview-Level Answer

If interviewer asks:

What is AOT?

> AOT (Ahead Of Time Compilation) is a compilation technique where bytecode is converted into native machine code before runtime. It improves startup time and reduces memory overhead, and is used in Android ART and GraalVM Native Image.
